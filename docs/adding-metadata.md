# Completing metadata

The Metadata Editor makes use of the Data Documentation Initiative (DDI Version 2.5), the Dublin Core (DCMI version X) metadata standards and ISO 19139 for geospatial information.

The table below provides an overview of the different metadata standards as related to the project. Each metadata standard is integrated into the template that will define the project.

![image](/media/Page23.png)

A thorough completion of the DDI and DCMI elements will significantly raise the value of the archiving work by providing users with the necessary information to put the study into its proper context and to understand its purpose.

The DDI requires completion of the following sections: Document Description, Study Description, Datasets, Variables Groups, and External Resources. Recommendations for each field included in the IHSN template are provided below.

::: info
The IHSN recommends using the standardized IHSN DDI/DCMI templates
(Study Template and External Resources Template). This Quick
Reference Guide is based on these two templates. Visit the IHSN
website to download the latest version of these templates,
available in multiple languages.
:::


**Overall recommendations:**

- As an archivist, you may need to seek assistance from key experts involved in some of the technical aspects of the survey.
- As a general rule, avoid using ALL CAPS when you fill DDI fields. Also, check the spelling of all entries. The Editor does not provide (yet) an automatic spell checker.
- Some of the examples below present an optimal documentation of some fields. In many cases, for past surveys, you will not find such detailed information. Try to provide as much detail as possible. For future surveys, the information should be compiled and provided during the whole life cycle of the survey. This will ensure that the best possible documentation is available at completion of that survey.

## Good practices for completing the Document Description

Documenting a study using the DDI and DCMI metadata standards consists of generating a metadata file which will be saved in XML format in what is called an *XML Document*. The *Document Description* described below is a description of that XML file. The IHSN Template selected 4 elements to describe the DDI document.

| Metadata Producer | Name of the person(s) or<br>organization(s) who documented<br>the dataset. Use the "role"<br>attribute to distinguish<br>different stages of involvement<br>in the production process.<br>Example:<br>*Name*<br>*National<br>Statistics<br>Office<br>(NSO)*<br>*International<br>Household<br>Survey<br>Network<br>(IHSN)* | *Role*<br>*Documentation<br>of the<br>study*<br>*Review of<br>the<br>metadata* |
| --- | --- | --- |
| Date of Production | This is the date (in ISO format<br>YYYY-MM-DD) the DDI document was<br>produced (not distributed or<br>archived). This date will be<br>automatically imputed when you<br>save the file. |  |
| DDI Document Version | Documenting a dataset is not a<br>trivial exercise. Producing<br>“perfect” metadata is probably<br>impossible. It may therefore<br>happen that, having identified<br>errors in a DDI document or<br>having received suggestions for<br>improvement, you decide to modify<br>the Document even after a first<br>version has been disseminated.<br>This element is used to identify<br>and describe the current version<br>of the document. It is good<br>practice to provide a version<br>number (and date), and<br>information on what distinguishes<br>this version from the previous<br>one(s) if relevant.<br>Example:<br>*Version 02 (July 2017). This<br>version is identical to version<br>01, except for the section on<br>Data Appraisal which was<br>updated.* |  |
| DDI Document ID Number | The ID number of a DDI document<br>is a unique number that is used<br>to identify this DDI file. Define<br>and use a consistent scheme to<br>use. Such an ID could be<br>constructed as follows:<br>DDI_COUNTRY_PRODUCER_SURVEY_YEAR<br>where<br>-  *country* is the 3-letter ISO<br>country abbreviation<br>-  *producer* is the abbreviation<br>of the producing agency<br>-  *survey* is the survey<br>abbreviation<br>-  *year* is the reference year<br>(or the year the survey<br>started)<br>- DDI document version number<br>Example:<br>*The DDI file related to the<br>Demographic and Health Survey<br>documented by staff from the<br>Uganda Bureau of Statistics in<br>2005 would have the following<br>ID:<br>DDI_UGA_UBOS_DHS_2005_v01. If<br>the same survey is documented by<br>a staff from the IHSN, this<br>would be<br>DDI_UGA_IHSN_DHS_205_v01.* |  |
| Collection | This field allows viewed and<br>searched the study by collection |  |
| Programs | Link surveys to projects / trust<br>funds |  |


## Good practices for completing the Study Description

In the DDI standard, the Study Description is the section that contains all elements needed to describe the study itself (investigators, dates and methods, scope and coverage, etc.)

| **Identification** |  |
| --- | --- |
| Survey Title | The title is the official name of<br>the survey as it is stated on the<br>questionnaire or as it appears in<br>the design documents. The<br>following items should be noted:<br>-  Include the reference year(s)<br>of the survey in the title.<br>-  Do not include the<br>abbreviation of the survey<br>name in the title.<br>-  As the survey title is a<br>proper noun, the first letter<br>of each word should be<br>capitalized (except for<br>prepositions or other<br>conjunctions).<br>-  Including the country name in<br>the title is optional.<br>Example:<br>-  *National Household Budget<br>Survey 2012-2013*<br>-  *Popstan Multiple Indicator<br>Cluster Survey 2012* |
| Survey Subtitle | Subtitle is optional and rarely<br>used. A subtitle can be used to<br>add information usually<br>associated with a sequential<br>qualifier for a survey.<br>Example:<br>*Title: Welfare Monitoring<br>Survey 2007*<br>*Subtitle: Fifth round* |
| Abbreviation or Acronym | The abbreviation of a survey is<br>usually the first letter of each<br>word of the titled survey. The<br>survey reference year(s) may be<br>included.<br>Example:<br>-  *DHS 2015 for “Demographic and<br>Health Survey 2005”*<br>-  *HIES 2012-2013 for “Household<br>Income and Expenditure Survey<br>2003”* |
| Study type | The study type or *survey type*<br>is the broad category defining<br>the survey. This item has a<br>controlled vocabulary (you may<br>customize the IHSN template to<br>adjust this controlled vocabulary<br>if needed). |
| Series information | A survey may be repeated at<br>regular intervals (such as an<br>annual labour force survey), or<br>be part of an international<br>survey program (such as the MICS,<br>CWIQ, DHS, LSMS and others). The<br>Series information is a<br>description of this “collection”<br>of surveys. A brief description<br>of the characteristics of the<br>survey, including when it<br>started, how many rounds were<br>already implemented, and who is<br>in charge would be provided here.<br>If the survey does not belong to<br>a series, leave this field empty.<br>Example:<br>*The Multiple Indicator Cluster<br>Survey, Round 3 (MICS3) is the<br>third round of MICS surveys,<br>previously conducted around 1995<br>(MICS1) and 2000 (MICS2). MICS<br>surveys are designed by UNICEF,<br>and implemented by national<br>agencies in participating<br>countries. MICS was designed to<br>monitor various indicators<br>identified at the World Summit<br>for Children and the Millennium<br>Development Goals.<br>Many questions and indicators in<br>MICS3 are consistent and<br>compatible with the prior round<br>of MICS (MICS2) but less so with<br>MICS1, although there have been a<br>number of changes in definition<br>of indicators between rounds.*<br>*Round 1 covered X countries,<br>round 2 covered Y countries, and<br>Round Z covered N countries.* |
| Translated title | In countries with more than one<br>official language, a translation<br>of the title may be provided.<br>Likewise, the translated title<br>may simply be a translation into<br>English from a country’s own<br>language. Special characters<br>should be properly displayed<br>(such as accents and other stress<br>marks or different alphabets). |
| Unique user defined ID Number | The ID number of a dataset is a<br>unique number that is used to<br>identify a particular survey.<br>Define and use a consistent<br>scheme to use. Such an ID could<br>be constructed as follows:<br>country-producer-survey-year-vers<br>ion<br>where<br>-  *country* is the 3-letter ISO<br>country abbreviation<br>-  *producer* is the abbreviation<br>of the producing agency<br>-  *survey* is the survey<br>abbreviation<br>-  *year* is the reference year<br>(or the year the survey<br>started)<br>-  *version* is the number<br>dataset version number (see<br>Version Description below)<br>Example:<br>*The Demographic and Health<br>Survey implemented by the Uganda<br>Bureau of Statistics in 2005<br>could have the following ID:*<br>*UGA-UBOS-DHS-2005-v01.* |
| Depositor | The name of the person<br>(or institution) who provided this<br>data collection to the archive<br>storing it. |
| Date of Deposit | The date that the data collection<br>was deposited with the archive that<br>originally received it. |
| **Version** |  |
| Version Description | The version description should<br>contain a version number followed<br>by a version label. The version<br>number should follow a standard<br>convention to be adopted by the<br>institute. We recommend that<br>larger series be defined by a<br>number to the left of a decimal<br>and iterations of the same series<br>by a sequential number that<br>identifies the release. Larger<br>series will typically include (0)<br>the raw, unedited dataset; (1)<br>the edited dataset, non<br>anonymized, for internal use at<br>the data producing agency; and<br>(2) the edited dataset, prepared<br>for dissemination to secondary<br>users (possibly anonymized).<br>Example:<br>-  *v00: Basic raw data,<br>obtained from data entry<br>(before editing)*.<br>-  *v01: Edited data, second<br>version, for internal use<br>only*.<br>-  *v02: Edited, anonymous<br>dataset for public<br>distribution*.<br>A brief description of the version<br>should follow the numerical<br>identification. |
| Production date | This is the date in ISO format<br>(yyyy-mm-dd) of actual and final<br>production of the data.<br>Production dates of all versions<br>should be carefully tracked.<br>Provide at least the month and<br>year. Use the calendar icon in<br>the Metadata editor to assure<br>that the date selected is in<br>compliance with the ISO format. |
| Version Notes | Version notes should provide a<br>brief report on the changes made<br>through the versioning process.<br>The note should indicate how this<br>version differs from other<br>versions of the same dataset. |
| **Study Authorization** |  |
| Authorizing Agency | Name of the agent or agency that<br>authorized the study. The<br>"affiliation" attribute indicates<br>the institutional affiliation of<br>the authorizing agent or agency.<br>The "abbr" attribute holds the<br>abbreviation of the authorizing<br>agent's or agency's name |
| Authorization Statement | The text of the authorization. Use<br>XHTML to capture significant<br>structure in the document<br>Example:<br>Required documentation covering<br>the study purpose, disclosure<br>information, questionnaire<br>content, and consent statements<br>was delivered to the OUHS on<br>2010-10-01 and reviewed by the<br>compliance officer. Statement of<br>authorization for the described<br>study was received on 2010-11-04 |
| Legal basis | Decree or law authorizing or<br>requiring the study<br>(e.g. census act) |
| **Overview** |  |
| Study Budget | Describe the budget of the project<br>in as much detail as needed.<br>Internal structure is allowed using<br>XHTML elements. Different<br>organizations express their budgets<br>in different formats and this open<br>format allows flexibility.<br>Attributes: Budget line ID, Budget<br>line label, Amount, Currency and<br>Source of funding. |
| Abstract | The abstract should provide a<br>clear summary of the purposes,<br>objectives and content of the<br>survey. It should be written by a<br>researcher or survey statistician<br>aware of the survey. |
| Objectives of the study | Describe the Main (explicit) and<br>secondary (explicit) objectives of<br>the survey. |
| Kind of data | This field is a broad<br>classification of the data and it<br>is associated with a drop-down<br>box providing controlled<br>vocabulary. That controlled<br>vocabulary includes 9 items but<br>is not limited to them. |
| Unit of analysis | A survey could have various units<br>of analysis. These are fairly<br>standard and are usually:<br>-  Household (household survey,<br>census)<br>-  Person (household survey,<br>census)<br>-  Enterprise (enterprise survey)<br>-  Commodity (household survey,<br>price survey)<br>-  Plots of land (agricultural<br>survey) |
| **Scope** |  |
| Description of scope | The scope is a description of the<br>themes covered by the survey. It<br>can be viewed as a summary of the<br>modules that are included in the<br>questionnaire. The scope does not<br>deal with geographic coverage.<br>Example:<br>The scope of the Multiple<br>Indicator Cluster Survey<br>includes:<br>-  *HOUSEHOLD: Household<br>characteristics, household<br>listing, orphaned and<br>vulnerable children,<br>education, child labour, water<br>and sanitation, household use<br>of insecticide treated<br>mosquito nets, and salt<br>iodization, with optional<br>modules for child discipline,<br>child disability, maternal<br>mortality and security of<br>tenure and durability of<br>housing.*<br>-  *WOMEN: Women's<br>characteristics, child<br>mortality, tetanus toxoid,<br>maternal and newborn health,<br>marriage, polygyny, female<br>genital cutting,<br>contraception, and HIV/AIDS<br>knowledge, with optional<br>modules for unmet need,<br>domestic violence, and sexual<br>behavior.*<br>-  *CHILDREN: Children's<br>characteristics, birth<br>registration and early<br>learning, vitamin A,<br>breastfeeding, care of<br>illness, malaria,<br>immunization, and<br>anthropometry, with an<br>optional module for child<br>development.* |
| Topic classifications | A topic classification<br>facilitates referencing and<br>searches in electronic survey<br>catalogs. Topics should be<br>selected from a standard<br>thesaurus, preferably an<br>international, multilingual<br>thesaurus. The IHSN recommends<br>the use of the thesaurus used by<br>the Council of European Social<br>Science Data Archives (CESSDA).<br>The CESSDA thesaurus has been<br>introduced as a controlled<br>vocabulary in the IHSN Study<br>Template version 1.3 (available<br>`www.surveynetwork.org/toolkit <h<br>ttp://www.surveynetwork.org/toolk<br>it>`__). |
| Keywords | Keywords summarize the content or<br>subject matter of the survey. As<br>topic classifications, these are<br>used to facilitate referencing<br>and searches in electronic survey<br>catalogs. Keywords should be<br>selected from a standard<br>thesaurus, preferably an<br>international, multilingual<br>thesaurus. Entering a list of<br>keywords is tedious. This option<br>is provided for advanced users<br>only. |
| **Quality Statement** |  |
| Standards Compliance | This section lists all specific<br>standards complied with during the<br>execution of this study. Note the<br>standard name and producer and how<br>the study complied with the<br>standard |
| Other Quality Statement | Enter any additional quality<br>statements |
| **Post Evaluation Procedures** |  |
| Evaluator Type | The evaluator element identifies<br>persons or organizations involved<br>in the evaluation. The Affiliation<br>attribute contains the affiliation<br>of the individual or organization.<br>The Abbr. attribute holds an<br>abbreviation for the individual or<br>organization. | Evaluation Outcomes | Describe the outcomes of the<br>evaluation |
| **Coverage** |  |
| Country | Enter the country name, even in<br>cases where the survey did not<br>cover the entire country. In the<br>field “Abbreviation”, we<br>recommend that you enter the<br>3-letter ISO code of the country.<br>If the dataset you document<br>covers more than one country,<br>enter all in separate rows. |
| Geographic coverage | This filed aims at describing at<br>what geographic level the data<br>are representative. Typical<br>entries will be “National<br>coverage”, “Urban (or rural)<br>areas only”, “state of …”,<br>“Capital city”, etc.<br>Note that we do not describe here<br>where the data was collected. For<br>example, as sample survey could<br>be declared as “national<br>coverage” even in cases where<br>some districts where not included<br>in the sample, as long as the<br>sampling strategy was such that<br>the representativity is national. |
| Geographic Unit | Lowest level of geographic<br>aggregation covered by the data. |
| Universe | We are interested here in the<br>survey universe (not the universe<br>of particular sections of the<br>questionnaires or variables),<br>i.e. in the identification of the<br>population of interest in the<br>survey. The universe will rarely<br>be the entire population of the<br>country. Sample household<br>surveys, for example, usually do<br>not cover homeless, nomads,<br>diplomats, community households.<br>Population censuses do not cover<br>diplomats. Try to provide the<br>most detailed information<br>possible on the population<br>covered by the survey/census.<br>Example:<br>*The survey covered all de jure<br>household members (usual<br>residents), all women aged 15-49<br>years resident in the household,<br>and all children aged 0-4 years<br>(under age 5) resident in the<br>household.* |
| Geographic bounding box | The geographic bounding box is the<br>minimum box, defined by west and<br>east longitudes and north and south<br>latitudes, that includes the<br>largest geographic extent of the<br>dataset's geographic coverage.<br>This element is used in the first<br>pass of a coordinate-based search.<br>If the Geographic bounding Polygon<br>element is included, then this<br>field element MUST be included |
| Geographic Bounding Polygon | This field allows the creation of<br>multiple polygons to describe in a<br>more detailed manner the geographic<br>area covered by the dataset. It<br>should only be used to define the<br>outer boundaries of a covered area.<br>Example:<br>In the United States, such polygons<br>can be created to define boundaries<br>for Hawaii, Alaska, and the<br>continental United States, but not<br>interior boundaries for the<br>contiguous states. This field is<br>used to refine a coordinate-based<br>search, not to actually map an area |
| **Producers and Sponsors.** |  |
| Authoring Entity/Primary<br>investigators | The primary investigator will in<br>most cases be an institution, but<br>could also be an individual in<br>the case of small-scale academic<br>surveys. The two fields to be<br>completed are the Name and the<br>Affiliation fields. Generally, in<br>a survey, the Primary<br>Investigator will be the<br>institution implementing the<br>survey. If various institutions<br>have been equally involved as<br>main investigators, then all<br>should be mentioned. This only<br>includes the agencies responsible<br>for the implementation of the<br>survey, not its funding or<br>technical assistance. The order<br>in which they are listed is<br>discretionary. It can be<br>alphabetic or by significance of<br>contribution. Individual persons<br>can also be mentioned. If persons<br>are mentioned use the appropriate<br>format of Surname, First name. |
| Producers | This field is provided to list<br>other interested parties and<br>persons that have played a<br>significant but not the leading<br>technical role in implementing<br>and producing the data. The<br>specific fields to be competed<br>are: Name of the organization,<br>Abbreviation, Affiliation and<br>Role. If any of the fields are<br>not applicable these can be left<br>blank. The abbreviations should<br>be the official abbreviation of<br>the organization. The role should<br>be a short and succinct phrase or<br>description on the specific<br>assistance provided by the<br>organization in order to produce<br>the data. The roles should be<br>standard vocabulary such as:<br>-  [Technical assistance in]<br>questionnaire design<br>-  [Technical assistance in]<br>sampling methodology /<br>selection<br>-  [Technical assistance in] data<br>collection<br>-  [Technical assistance in] data<br>processing<br>-  [Technical assistance in] data<br>analysis<br>Do not include here the financial<br>sponsors. |
| Funding Agency/Sponsor | List the organizations (national<br>or international) that have<br>contributed, in cash or in kind,<br>to the financing of the survey.<br>The government institution that<br>has provided funding should not<br>be forgotten. |
| Other Identifications/<br>acknowledgements | This optional field can be used<br>to acknowledge any other people<br>and institutions that have in<br>some form contributed to the<br>survey. |
| **Sampling** |  |
| Sampling procedure | This field only applies to sample<br>surveys. Information on sampling<br>procedure is crucial (although<br>not applicable for censuses and<br>administrative datasets). This<br>section should include summary<br>information that includes though<br>is not limited to:<br>-  Sample size<br>-  Selection process (e.g.,<br>probability proportional to<br>size or over sampling)<br>-  Stratification (implicit and<br>explicit)<br>-  Stages of sample selection<br>-  Design omissions in the sample<br>-  Level of representation<br>-  Strategy for absent<br>respondents/not found/refusals<br>(replacement or not)<br>-  Sample frame used, and listing<br>exercise conducted to update<br>it<br>It is useful also to indicate<br>here what variables in the data<br>files identify the various levels<br>of stratification and the primary<br>sample unit. These are crucial to<br>the data users who want to<br>properly account for the sampling<br>design in their analyses and<br>calculations of sampling errors.<br>This section accepts only text<br>format; formulae cannot be<br>entered. In most cases, technical<br>documents will exist that<br>describe the sampling strategy in<br>detail. In such cases, include<br>here a reference<br>(title/author/date) to this<br>document, and make sure that the<br>document is provided in the<br>External Resources.<br>Example:<br>*5000 households were selected<br>for the sample. Of these, 4996<br>were occupied households and 4811<br>were successfully interviewed for<br>a response rate of 96.3%. Within<br>these households, 7815 eligible<br>women aged 15-49 were identified<br>for interview, of which 7505 were<br>successfully interviewed<br>(response rate 96.0%), and 3242<br>children aged 0-4 were identified<br>for whom the mother or caretaker<br>was successfully interviewed for<br>3167 children (response rate<br>97.7%). | Sample Frame Name | Sample frame describes the sampling<br>frame used for identifying the<br>population from which the sample<br>was taken. Label and text<br>describing the sample frame |
| Update of listing | Describes operations conducted to<br>update the sample frame |
| Valid Period | Defines a time period for the<br>validity of the sampling frame.<br>Enter dates in YYYY-MM-DD format. |
| Custodian | Custodian identifies the agency or<br>individual who is responsible for<br>creating or maintaining the sample<br>frame. Attribute affiliation<br>provides the affiliation of the<br>custodian with an agency or<br>organization. Attribute abbr.<br>provides an abbreviation for the<br>custodian. |
| Use Statement | Sample frame use statement |
| Frame Unit | Provides information about the<br>sampling frame unit. The attribute<br>"is Primary" is boolean, indicating<br>whether the unit is primary or not. |
| Reference Period | Indicates the period of time in<br>which the sampling frame was<br>actually used for the study in<br>question. Use ISO 8601 date/time<br>formats to enter the relevant<br>date(s). |
| Sample Size | This element provides the targeted<br>sample size in integer format.<br>Attributes: Planned / Actual and<br>Unit and Number. |
| Sample Size Formula | This element includes the formula<br>that was used to determine the<br>sample size |
| Stratification | Describe the Stratification<br>(implicit and explicit) and the<br>Variables identifying strata and<br>PSU |
| Deviation from sample design | This field only applies to sample<br>surveys.<br>Sometimes the reality of the<br>field requires a deviation from<br>the sampling design (for example<br>due to difficulty to access to<br>zones due to weather problems,<br>political instability, etc). If<br>for any reason, the sample design<br>has deviated, this should be<br>reported here. |
| Response rate | Response rate provides that<br>percentage of households (or<br>other sample unit) that<br>participated in the survey based<br>on the original sample size.<br>Omissions may occur due to<br>refusal to participate,<br>impossibility to locate the<br>respondent, or other. Sometimes,<br>a household may be replaced by<br>another by design. If more than one<br>variable is a weighting variable,<br>describe how these variables<br>differ from each other and what<br>the purpose of each one of them<br>is.<br>Example:<br>*Sample weights were calculated<br>for each of the data files.*<br>*Sample weights for the household<br>data were computed as the inverse<br>of the probability of selection<br>of the household, computed at the<br>sampling domain level<br>(urban/rural within each region).<br>The household weights were<br>adjusted for non-response at the<br>domain level, and were then<br>normalized by a constant factor<br>so that the total weighted number<br>of households equals the total<br>unweighted number of households.<br>The household weight variable is<br>called HHWEIGHT and is used with<br>the HH data and the HL data.*<br>*Sample weights for the women's<br>data used the un-normalized<br>household weights, adjusted for<br>non-response for the women's<br>questionnaire, and were then<br>normalized by a constant factor<br>so that the total weighted number<br>of women's cases equals the total<br>unweighted number of women's<br>cases.*<br>*Sample weights for the<br>children's data followed the same<br>approach as the women's and used<br>the un-normalized household<br>weights, adjusted for<br>non-response for the children's<br>questionnaire, and were then<br>normalized by a constant factor<br>so that the total weighted number<br>of children's cases equals the<br>total unweighted number of<br>children's cases.* |

The Variable Description is the section of the DDI document that provides detailed information on each variable.

## Good practices for completing the External Resources description

The External Resources are all materials related to the study others than the data files. They include documents (such as the questionnaires, interviewer's manuals, reports, etc), programs (data entry, editing, tabulation, and analysis), maps, photos, and others. To document external resources, the Metadata Editor uses the Dublin Core metadata standard (which complements the DDI standard).
